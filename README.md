# 滤芯寿命台账

共三张相互独立的记录：

| 记录 | 存放位置 | 说明 |
| --- | --- | --- |
| 滤芯更换 | `machines[].filters[]` | 一条记录 = 一次寿命边界（安装 → 更换）。换机后即使批号相同，也从新装日期重新起算，不按批号合并。 |
| 机器负载 | `machines[].load[]` | 按日期区间记录吨/日、小时/日，用来把寿命换算成工作小时或处理吨数。 |
| 洗液余量 | `machines[].wash` + `machines[].washLog[]` | 容量、日损耗、补液记录。余量单独结算，不混进寿命样本。 |

## 运行

```bash
node server.js                 # 默认 3000 端口
PORT=8080 node server.js       # 读取 PORT
```

服务只绑定 `127.0.0.1`。首次启动会在 `data/state.json` 生成一份本地演示数据（4 台设备、15 条寿命样本，其中 11 条已结束、4 条仍在用）。可用 `DATA_FILE=/path/to/state.json` 指定其它数据文件。

```bash
node --test test/*.test.js     # 或 npm test
```

## 页面上的三个操作

1. **估计原耗材寿命** — 选口径（日龄 / 工作小时 / 处理吨数）后计算。仍在用的滤芯按右删失处理：只进风险集，不当成已失效时间。给出中位寿命、P10–P90 区间、95% 置信区间，以及每台在用设备的预计更换日期区间。已结束寿命少于 5 条时结果标为「临时」。
2. **补录更换工单** — 先登记为待应用（不改寿命边界），点「应用并保留旧估计」后才写回更换日期、自动开启下一条寿命，并把应用前的旧估计与应用后的新估计一起留在历史里，两套并排展示。
3. **查看负载和样本边界** — 机器卡片展示负载区间、洗液余量与逐条样本边界（已结束 / 仍在用 / 随设备停用结束观察）；「比较两种口径」按相同日龄窗口与按工作小时配齐分别预测，标出相差 ≥30 天、结论会变的设备。

业务结果区带 `data-evidence-result` 与 `data-last-action` 属性，`data-evidence-result` 的值为 `<动作>|<状态>|<摘要哈希>`，每次操作都会刷新；完整 JSON 摘要同时写进区域正文。页头 `data-evidence-status` 显示 `ok` / `error`，便于核对操作前后的内容。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 设备、样本、工单、历史 |
| GET | `/api/estimate?basis=days\|hours\|tons` | 寿命估计与在用设备预测 |
| GET | `/api/compare` | 日龄 vs 工作小时口径比较 |
| GET | `/api/boundaries` | 每条滤芯的样本边界 |
| POST | `/api/workorders` | 补录工单（校验失败 400 / 重复 409） |
| POST | `/api/workorders/:id/apply` | 应用工单，返回旧/新估计 |
| POST | `/api/reset` | 恢复演示数据 |

## 统计口径

- 生存曲线用 Kaplan–Meier，Greenwood 方差 + log-log 置信区间。
- 分位数取「生存率首次跌到阈值」的时间点，不插值；观察上限之外返回 `null`，不做外推。
- 负载按日期区间精确折算：`间隔天数 × 该区间日负载`。
- 设备停用后，未拆下的滤芯观察截止停用日，仍按删失处理。
